# depres - 确定性依赖版本解析工具

## 概述

`depres` 是一套确定性的依赖版本解析系统。多个模块各自声明依赖与版本范围，`depres` 将这些声明合并成一张依赖图，求解出唯一确定的版本组合。

### 核心特性

- **确定性求解**：相同输入下，无论模块顺序、并发程度或进程重启与否，得到的版本组合逐字段一致。
- **多版本并存**：同一依赖的多个不兼容大版本可以在结果中并存，传递依赖不跨大版本串味。
- **冲突可解释**：无法同时满足全部约束时，给出可读说明并指明矛盾来源。
- **异常可区分**：环、依赖缺失、非法版本范围等异常按可区分的原因失败，不会死循环或崩溃。
- **工作区支持**：多个成员各自持有清单并相互引用，求解跨成员进行；新增或移除成员不改变与它无关的既有结论。
- **锁定与校验**：把一次求解固化成可复现的锁定结果，支持安装与校验；清单与锁定结果不一致时识别缺项与漂移。
- **增量求解**：清单小幅变化后只重算受影响部分，增量结论与全量重算完全一致。
- **本地优先**：可用版本信息只来自本地 registry，不依赖外部网络。

## 求解语义

### 槽位模型

求解器将每个依赖映射到一个**槽位**（Slot）。槽位由 `(包名, 兼容边界)` 唯一标识。同一槽位内的所有约束必须由同一个版本满足。

兼容边界由兼容策略决定：

| 策略 | 边界 | 说明 |
|------|------|------|
| `major`（默认） | 大版本 | 同一大版本内共享一个版本（语义化版本兼容） |
| `minor` | 大版本.小版本 | 同一小版本内共享一个版本 |
| `exact` | 精确版本 | 每个版本独立槽位（不共享） |
| `unified` | 无边界 | 所有版本共享一个槽位（类似 pip 全局单版本） |

### 求解算法

求解器使用回溯算法（backtracking）：

1. 收集所有根依赖边，按依赖名排序。
2. 对每条依赖边，确定候选兼容边界（按最高版本降序）。
3. 对每个边界，选择满足所有约束的最高版本。
4. 递归求解该版本的传递依赖。
5. 若传递依赖求解失败，回溯尝试下一个版本或边界。
6. 所有边界都失败时，返回冲突错误。

### 确定性保证

- 依赖边按名称排序处理。
- 候选边界按最高版本降序排列。
- 版本按降序尝试。
- 结果槽位按 `(名称, 边界)` 排序输出。
- 不使用并发，避免并发导致的不确定性。

### 多版本并存

在 `major` 策略下，`foo@^1.0.0` 和 `foo@^2.0.0` 属于不同槽位（边界 1 和 2），可以并存。传递依赖也在各自的槽位中求解，不跨大版本串味。

### 冲突解释

当无法满足全部约束时，冲突错误包含：

- 每个约束的来源（哪个模块/包声明的）。
- 约束的具体内容。
- 矛盾来源汇总。

### 可读说明输出（`-explain`）

求解成功后，`-explain` 输出求解结果的可读说明。其内容范围与边界情形：

- **覆盖全部槽位**：结果中的每个槽位都会呈现，按 `(包名, 兼容边界)` 排序分组输出；同一份求解结论每次输出的内容和顺序完全一致。
- **未选定槽位如实呈现**：求解过程中探索过、但因回溯最终没有落到具体版本的槽位（候选边界）不会跳过，也不会含糊带过，而是以 `<未选定>` 明确标注，例如：
  `lib: <未选定> (boundary=2), 1.0.0 (boundary=1)`。
- **不崩溃保证**：任何能够求解成功的输入，说明输出都必须完整且可读；未选定槽位不会导致空指针崩溃。

### 异常处理

| 异常类型 | 说明 |
|----------|------|
| `ConflictError` | 约束冲突，无法同时满足 |
| `CycleError` | 检测到依赖环 |
| `MissingDepError` | 依赖在 registry 中不存在 |
| `InvalidRangeError` | 版本范围格式非法 |
| `ResolutionError` | 其他求解错误（如取消） |

## 版本约束语法

| 语法 | 示例 | 说明 |
|------|------|------|
| 精确版本 | `1.2.3` | 仅匹配 1.2.3 |
| 插入号 | `^1.2.3` | >=1.2.3 <2.0.0 |
| 波浪号 | `~1.2.3` | >=1.2.3 <1.3.0 |
| 比较级 | `>=1.0.0 <2.0.0` | 合取（AND） |
| 通配符 | `1.x`, `1.2.x` | 匹配大版本或小版本 |
| 任意版本 | `*` | 匹配所有版本 |
| 析取 | `^1.0.0 \|\| ^2.0.0` | 析取（OR） |

### 插入号规则

- `^1.2.3` := `>=1.2.3 <2.0.0`
- `^0.2.3` := `>=0.2.3 <0.3.0`
- `^0.0.3` := `>=0.0.3 <0.0.4`

### 预发布版本

- 预发布版本（如 `1.0.0-beta.1`）小于正式版本。
- 预发布标识符按语义化版本规则比较（数字 < 字符串）。

## 工作区

工作区配置文件（`depres-workspace.json`）：

```json
{
  "members": ["app/package.json", "lib/package.json"]
}
```

成员清单可以使用 `workspace:*` 引用其他成员：

```json
{
  "name": "app",
  "dependencies": {
    "lib": "workspace:*",
    "foo": "^1.0.0"
  }
}
```

`workspace:*` 引用解析为成员的精确版本。工作区成员优先于本地 registry。

## 锁定文件

锁定文件格式（`depres-lock.json`）：

```json
{
  "format": "depres-lock/v1",
  "registry_fingerprint": "sha256:...",
  "policy": "major",
  "members": ["app"],
  "slots": [
    {
      "name": "foo",
      "boundary": "1",
      "version": "1.5.0",
      "integrity": "sha256:...",
      "edges": [
        {"name": "bar", "constraint": "^1.5.0"}
      ]
    }
  ]
}
```

### 可复现性保证

相同输入（清单、本地 registry、兼容策略、成员集合）下，锁定结果**逐字节一致**：

- 不随运行时刻变化：锁定内容不包含时间戳等运行时数据（`resolved_at` 字段已移除）。
- 不随机器、进程重启或并发与否变化：所有输出集合（成员、槽位、依赖边）均显式排序后写入。
- 不随清单声明顺序变化：根依赖边与成员列表在求解和写入前均按确定性顺序排序。

求解过程中探索过但最终未选定版本的槽位（回溯留下的候选边界）**不会**写入锁定结果。

### 旧锁定文件兼容

- 旧版锁定文件（含 `resolved_at` 等已移除字段）仍可正常读取、校验和使用，不会失效。
- 读取时遇到已移除的字段会兼容忽略，并给出可区分的提示，例如：
  `锁定文件包含已移除的字段 "resolved_at"，已兼容忽略（该字段不再写入，不影响校验与使用）`。
- CLI 的 `install` 与 `verify` 命令会将兼容提示打印到 stderr（前缀 `兼容提示:`），不影响正常输出与退出码。
- 程序化读取可使用 `resolver.ReadLockCompat(path)` 获取提示列表；`resolver.ReadLock(path)` 保持旧签名，静默忽略。

验证方法：对旧锁定文件执行 `depres verify` 或 `depres install`，应观察到 stderr 上的兼容提示且命令正常完成；重新执行 `depres resolve` 会写出不含已移除字段的新锁定文件。

### 校验策略

| 策略 | 说明 |
|------|------|
| `strict` | 任何不一致都报错（默认） |
| `warn` | 报告不一致但继续 |
| `update` | 重新求解并更新锁定文件 |

### 缺项与漂移

- **缺项**：清单中有依赖边，但锁定文件中没有满足的槽位。
- **漂移**：锁定文件中的版本与 registry 不一致（内容变更或版本移除）。

## 增量求解

增量求解器使用缓存加速：

- 缓存键：`(包名, 兼容边界, 排序后的约束集合)`。
- 当槽位的约束集合不变时，复用缓存的版本和依赖边。
- 当约束集合变化时，重新求解该槽位。
- 增量结论与全量重算完全一致（通过测试验证）。

### 取消与超时

- 求解器支持 `context.Context`，可随时取消。
- 取消后不写入锁定文件（原子写入：先写临时文件再重命名）。

## CLI 使用

### 求解

```bash
depres resolve -registry ./registry -manifest app.json -explain
```

### 安装

```bash
depres install -registry ./registry -lock depres-lock.json -target node_modules
```

### 校验

```bash
depres verify -registry ./registry -manifest app.json -lock depres-lock.json -policy strict
```

## 测试

```bash
go test ./resolver/ -v
```

测试覆盖：

- 确定性（模块顺序无关）
- 冲突与解释
- 多版本并存
- 工作区（新增/移除成员）
- 锁定校验（缺项与漂移）
- 锁定可复现性（多次运行、并发、进程重启、清单顺序变化下逐字节一致）
- 旧锁定文件兼容读取（已移除字段的提示与忽略）
- 说明输出（含未选定槽位的场景不崩溃、内容完整、顺序确定）
- 增量求解（与全量一致）
- 异常输入（环、缺失、非法范围）
- 兼容策略可配置性
- 钻石依赖
- 大规模确定性
